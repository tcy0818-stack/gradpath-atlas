## How to use this file

* One authorised phase per run, one pending task at a time: run its gate, then update its checkbox (Brief p.37; L3 p.34). After the last task of a phase: update docs, report, suggest a commit message, **STOP** and wait for the student's go-ahead.
* `- [x]` only after the gate has actually passed, with brief evidence. Unperformed or blocked checks stay `- [ ]` with `⛔ BLOCKED:` and the exact follow-up.
* **3-strike rule** (Brief p.39): after three failed attempts at one problem, stop, record the error, attempts and next diagnostic step under the task, and wait. No destructive Git cleanup.
* If a task changes the plan, update `PRD.md` and add a line to the change log.
* Tasks are atomic (one change, one gate) and ordered by dependency within each module; the phase map gives the build sequence (Brief pp.35–36).

**Evidence tags:** **A** = run or observed by the agent (PGlite = in-process PostgreSQL with a test-only Supabase shim, *not* a Supabase run). **S** = student-reported, output not seen by the agent. **S\*** = covered by the student's blanket report of 2026-10-26 that all remaining manual checks were completed on the live site; no per-check output supplied.

**Gate types:** **DOC** document audit · **BUILD** `npm run build` clean (Brief p.35) · **TEST** `npm test` · **LINT** `npm run lint` + typecheck · **DEV** `npm run dev` renders on `localhost:3000`, no console errors (Brief p.35) · **DB** migration/SQL run on a real Supabase project, rows/policies inspected (Brief p.35) · **VIS** viewports 1440/768/375 px (Brief p.35) · **MAN** manual check against the acceptance criteria.

**Task line format:** `- [x] **ID** · Phase · Req IDs — change · *Depends:* … · **Gate (type):** what must be true. *Evidence:* tag and short result.`
